# AI-380 구현 계획 — 2D LLM Clarification Artifact 발행

> 브랜치: `feat/AI-S14P31A204-380-2d-llm-clarification-artifact`
> 전제: 버튼 클릭 방식 (Option B). 텍스트 재답변(conversation_history) 연동은 이번 범위 밖.

---

## 목표

clarification이 필요할 때 워커가 MinIO에 구조화된 아티팩트를 업로드하고,
`ClarificationRequiredError.detail_storage_url`을 통해 BE/FE가 아티팩트를 내려받을 수 있게 한다.
FE는 `alternatives[].title` 을 버튼으로 렌더링하고, 클릭 시 `fill` 데이터로 구체적인 후속 명령을 구성한다.

---

## 끊긴 지점 (현재 상태)

```
worker.py:350  preview status == "needs_clarification" | "alternatives"
    ↓
raise ClarificationRequiredError(
    code="CLARIFICATION_REQUIRED",
    message=str(preview.get("summary")),   ← 텍스트 한 줄만 전달
    clarification_request_id=...           ← ID는 있음
)
    ↓
ClarificationRequiredError.detail_storage_url = None  ← 항상 None
    ↓
이벤트에 detailStorageUrl 없음 → BE/FE가 alternatives 데이터를 받을 방법 없음
```

## 아키텍처 목표

```
worker.py — clarification path
    ↓ preview dict (status="needs_clarification"|"alternatives", alternatives=[...])
    ↓ ClarificationArtifact 생성
    ↓ MinIO 업로드  →  s3://…/steps/001/clarification/detail.v1.json
    ↓ ClarificationRequiredError.detail_storage_url = MinIO URL
    ↓ raise

event_factory — build_clarification_event
    ↓ to_event_error_payload → detailStorageUrl 포함

BE TwoDLlmEventListener (담당자 작업)
    ↓ EVENT_TWO_D_LLM_CLARIFICATION_REQUIRED 핸들러
    ↓ chat_log 저장, job status=NEEDS_CLARIFICATION

FE useLlmEdit.ts (FE-381 작업)
    ↓ polling 종료 조건 + MinIO 아티팩트 fetch
    ↓ AssistantPanel — 버튼 칩 렌더링
```

### ClarificationArtifact 스키마
```python
class ClarificationAlternative(BaseModel):
    alternative_id: str
    title: str              # FE 버튼 레이블
    description: str
    fill: dict[str, object] # 버튼 클릭 시 FE가 채울 파라미터
    affected_entities: list[str] = []
    warnings: list[str] = []
    metrics: list[str] = []

class ClarificationArtifact(BaseModel):
    schema_version: str = "v1"
    kind: Literal["needs_clarification", "alternatives"]
    question: str           # FE에 표시할 질문 문장
    alternatives: list[ClarificationAlternative] = []
    parsed_command_preview: dict[str, object] | None = None
    policy_plan: dict[str, object] | None = None
    job_id: str
    step_no: int
    clarification_request_id: str
    timestamp: datetime     # UTC ISO 8601
```

## 주의 사항

### _run_pipeline 파라미터 변경 영향
`test_worker.py`의 기존 `_fake_run_pipeline` mock들이 `**_: object`로 나머지 파라미터를 흡수하고 있어
시그니처 변경 시 기존 테스트는 깨지지 않는다.
단, `test_two_d_llm_worker_emits_clarification_with_job_step_id` 테스트는
`clarification_request_id`만 캡처하고 있으므로 `s3_client`가 추가되면
`_fake_run_pipeline`에서 S3 업로드 호출이 없어 upload 테스트만 별도 작성한다.

### Phase 2 에서 `_run_pipeline` 에 s3_client 파라미터 추가 시
`run_two_d_llm_job()` (로컬 실행용 진입점)에도 `s3_client` 파라미터를 optional로 추가하고
None인 경우 MinIO 업로드를 건너뛰어야 한다.
(로컬 smoke 실행에서 MinIO 연결 없이도 clarification 경로가 동작해야 함)
